# 公演情報の手動投入：入力規則

**注意**：このフォルダのサンプルは **架空のデータ** です。実在の公演情報ではありません。実データは、利用条件を確認した情報源からのみ作成してください（現時点で実データはありません）。

## ファイル
- `テンプレート_空.csv`：入力の見本（ヘッダーのみ）。コピーして使う。
- `サンプル_架空データ.csv`：動作確認用の架空データ（3行）。
- `設定_テンプレート.json`：アーティストと情報源の登録例（架空）。

## 列（この順番・この名前）
| 列 | 必須 | 規則 |
|---|---|---|
| artist_name | 必須 | アーティスト名（設定ファイルの名前と一致させる） |
| venue | 必須 | 会場名 |
| name | 必須 | 公演名 |
| event_date | 任意 | `YYYY-MM-DD`（例：2027-03-01）。不明なら空欄 |
| status | 任意 | 公演発表／延期／中止／変更。空欄は「公演発表」 |
| evidence_url | 推奨 | 出典の公式URL（https://…） |
| source_performance_id | 推奨 | 公式サイト側の公演ID（会場が変わっても同じ公演として扱うため） |
| sale_type | 任意 | 先行受付／一般発売／リセール／抽選受付（1行に1つの発売） |
| sale_start | sale_type を書く場合は必須 | `YYYY-MM-DDTHH:MM:SS+09:00`（タイムゾーン必須） |
| sale_end | 任意 | 同上 |

- 同じ公演で発売が複数ある場合は、発売ごとに1行ずつ書く（公演の情報は同じ値にする）。
- 必須列が空の行、日付・日時の形式が違う行、発売の種類が不正な行は **取り込まれず、理由つきで報告** されます。
- 日時にタイムゾーンがないもの（例：2026-11-10 10:00）は拒否されます。

## 投入方法（このフォルダで実行）
1. 設定ファイルの `sources` に、情報源のIDを登録する（`src_manual` など。自動取得はしない）。
2. 入力CSVを作る（テンプレートをコピーして、別名で保存）。
3. 投入：
   `python3 artist_watch_run.py --dir ./artist_watch_data --config ./artist_watch_input/設定_テンプレート.json --source src_manual --batch <入力.csv>`
4. ホームを作り直す：
   `python3 artist_watch_home.py build --dir ./artist_watch_data --site ~/Desktop/巨大情報収集_ホーム --label "データ出所：手動入力（CSV）"`
5. 表示：`python3 artist_watch_home.py serve ...` → http://127.0.0.1:8765/index.html

同じCSVを再投入しても、公演は重複しません。日程や発売を変えて投入すると、変更履歴に残ります。

## 注意
- 定期実行は未接続です。このCSVは、人が手で作って投入するものです。
- 公演情報は、公式の情報源で確認してから入力してください。
